# Tracker Markdown 格式规范

本文档描述了用于定义毕业论文流程跟踪数据的自定义 Markdown 语言。编写 `.md` 文件后，可通过转换工具生成系统所需的 JSON 数据。

## 转换工具

```bash
# Markdown → JSON（覆盖 tracker.json）
pixi run md2json -- data/tracker.md -o data/tracker.json

# JSON → Markdown（反向导出）
pixi run json2md -- data/tracker.json -o data/tracker.md

# JSON → 数据库
pixi run db-import
```

## 文件结构总览

```
# 站点标题                          ← 一级标题：页面标题
站点描述（支持 Markdown 链接）       ← 紧跟的段落：页面描述

> ROLE value label desc color       ← 引用块：身份定义
> ROLE value label desc color

## 一、阶段标题                      ← 二级标题：阶段
阶段描述                             ← 紧跟的段落：阶段说明

### 任务名称 [applies_to]            ← 三级标题：任务
任务描述（注意事项）                  ← 段落：notes

- [applies_to] 子任务内容            ← 列表项：子任务
- 文件名 [applies_to]                ← 列表项：子文件（后跟缩进块）
  - 格式: ...
  - 命名: ...
  - 描述...
- @名称 时间 [applies_to] 备注       ← 列表项：时间节点
```

## 各元素详细说明

### 1. 站点标题

一级标题 `#` 定义页面主标题，只有一个。

```
# 厦门大学信息学院 研究生毕业论文流程跟踪
```

### 2. 站点描述

紧跟在一级标题后的段落，支持 Markdown 内联格式（链接、加粗等）。

```
来源：[信息学院（国家示范性软件学院）](https://informatics.xmu.edu.cn/)。
详细说明见[原文链接](https://informatics.xmu.edu.cn/info/2301/178021.htm)。
```

多段描述会被合并为一个字符串（段落间用空格连接）。

### 3. 身份定义

使用引用块格式 `> ROLE` 定义用户身份，每个身份一行。

**格式**：
```
> ROLE value label description color
```

**字段说明**：

| 字段 | 必填 | 说明 | 示例 |
|------|------|------|------|
| value | 是 | 身份标识（英文） | `doctor` |
| label | 是 | 显示名称 | `博士` |
| description | 否 | 身份描述 | `学术型博士研究生` |
| color | 否 | 标签颜色 | `purple`、`blue`、`green` |

**示例**：
```
> ROLE doctor 博士 学术型博士研究生 purple
> ROLE master 学术硕士 学术型硕士研究生 blue
> ROLE professional 专业硕士 专业学位硕士研究生 green
```

### 4. 阶段

二级标题 `##` 定义流程阶段。

**格式**：
```
## 阶段标题
阶段描述（可选）
```

**示例**：
```
## 一、定稿送审
完成论文定稿、查重、送审等准备工作
```

### 5. 任务

三级标题 `###` 定义任务，必须包含 `[applies_to]` 标记。

**格式**：
```
### 任务名称 [applies_to]
```

**applies_to 可选值**：

| 值 | 说明 |
|------|------|
| `all` | 所有身份可见 |
| `doctor` | 仅博士 |
| `master` | 仅学术硕士 |
| `professional` | 仅专业硕士 |

**示例**：
```
### 博士论文质量核查 [doctor]
### 毕业图像采集 [all]
```

### 6. 注意事项（Notes）

任务标题后的普通段落，每段为一条 note。支持 Markdown 内联格式。

```
### 系统上进行送审申请 [all]

仅学分全部完成、预答辩完成（博士）且毕业图像采集已完成的同学方有权限申请。

填写论文相关信息时，**严格按照各栏目字数要求填写，不要超过限定字数**。
```

解析结果：`notes: ["仅学分全部完成...", "填写论文相关信息时，**严格按照...**"]`

### 7. 子任务

以 `- [applies_to]` 开头的列表项。

**格式**：
```
- [applies_to] 子任务内容
```

**示例**：
```
- [all] 论文经导师同意后定稿
- [doctor] 首次定稿后进行预答辩（一般安排在正式答辩的3个月前）
- [all] 严格按照论文格式规范排版
```

### 8. 子文件

以 `- 文件名 [applies_to]` 开头，后跟缩进的字段描述块。

**格式**：
```
- 文件名 [applies_to]
  - 格式: 格式要求
  - 命名: 命名规则
  - 其他描述信息
```

**缩进字段说明**：

| 前缀 | 说明 |
|------|------|
| `格式:` | 文件格式要求，如 `PDF，小于20M` |
| `命名:` | 命名规则，如 `10384_学号_LW.pdf` |
| 其他 | 作为 description（可多行，自动合并） |

**示例**：
```
- 盲审论文电子版 [all]
  - 格式: PDF
  - 命名: 10384_学号_LW.pdf（学号中字母大写）
  - 1份。LW是字母，不是论文题目。

- 《学位申请表》 [all]
  - 格式: 彩色打印签字
  - 2份。查重通过后在系统内申请学位并打印。
```

### 9. 时间节点

以 `- @` 开头的列表项。

**格式**：
```
- @名称 时间 [applies_to] 备注
```

**字段说明**：

| 字段 | 必填 | 说明 | 示例 |
|------|------|------|------|
| 名称 | 是 | 节点名称 | `截止`、`预计`、`提交截止` |
| 时间 | 是 | 日期或相对描述 | `2026年4月初`、`答辩前至少5天` |
| applies_to | 是 | 身份标识 | `all`、`doctor` |
| 备注 | 否 | 补充说明 | `查重通过后方可送审` |

**示例**：
```
- @截止 2026年3月中旬 [all] 注意学院通知
- @预答辩截止 2026年3月中旬 [doctor] 博士生预答辩一般安排在正式答辩前3个月
- @截止 2026年5月底前 [all]
```

## 完整示例

```
# 厦门大学信息学院 研究生毕业论文流程跟踪

来源：[信息学院](https://informatics.xmu.edu.cn/)。详细说明见[原文](https://informatics.xmu.edu.cn/info/2301/178021.htm)。

> ROLE doctor 博士 学术型博士研究生 purple
> ROLE master 学术硕士 学术型硕士研究生 blue
> ROLE professional 专业硕士 专业学位硕士研究生 green

## 一、定稿送审
完成论文定稿、查重、送审等准备工作

### 毕业图像采集 [all]

注意通知并及时完成，该图像用于毕业证、学位证以及学信网。

- @截止 2026年3月中旬 [all] 注意学院通知

### 科研成果（创新性成果）审核 [all]

之前已审核过则无须重复进行。按要求提供科研成果证明材料。

通过邮件提醒研究生秘书审核，邮件名格式：科研成果审核（专利/论文/竞赛）-姓名-学号。

- [all] 准备科研成果证明材料
- [all] 系统上填写科研成果
- [all] 请导师在系统上审核通过
- [all] 邮件提醒研究生秘书审核

- @建议完成 2026年3月底前 [all] 尽早完成以免耽误后续流程

### 论文定稿（含预答辩） [all]

硕士论文字数不少于 **3万字**，博士不少于 **5万字**。

- [all] 论文经导师同意后定稿
- [doctor] 首次定稿后进行预答辩
- [doctor] 预答辩通过后可再次修改，经导师确认后再次定稿
- [all] 严格按照论文格式规范排版

- @预答辩截止 2026年3月中旬 [doctor] 博士生预答辩一般安排在正式答辩前3个月
- @论文定稿 2026年4月初 [all]

## 二、答辩
完成论文质量核查、答辩准备及正式答辩

### 正式答辩 [all]

请务必在每批次要求的答辩截止时间前完成答辩。

- [all] 按要求进行答辩
- [all] 答辩秘书记录和录音

- @截止 2026年5月底前 [all] 务必在批次要求的答辩截止时间前完成

## 三、答辩后提交材料

### 提交纸质版论文答辩材料及申请学位材料 [all]

除学位论文外，其他材料按顺序整理好装入档案袋。

- [all] 填写《研究生学位档案卷内目录》1份
- [all] 准备所有纸质材料
- [all] 将材料装入档案袋
- [all] 提交至研究生秘书处

- 《研究生学位档案卷内目录》 [all]
  - 格式: 打印
  - 1份，不得修改项目名称。

- 《学位论文正稿（第二次）》 [all]
  - 格式: 胶装，有图页面须彩印
  - 博士5本，硕士4本。前两页声明需手写签名。

- @形式审查截止 2026年6月上旬 [all] 先提交1本用于形式审查
- @全部材料截止 2026年6月中旬 [all] 逾期不予提交至学位评定分委员会
```

## 注意事项

1. **缩进**：子文件的字段描述必须用 2 个空格缩进
2. **空行**：各元素之间用空行分隔，空行是解析边界
3. **applies_to 必填**：任务标题和时间节点的 `[applies_to]` 必须填写
4. **加粗等内联格式**：注意事项中的 `**加粗**` 会被保留，前端用 Markdown 渲染
5. **反向转换**：`json2md` 可将 JSON 导出为此格式，方便编辑后再导入
